# 주제 탐색·검증 개선 기록

작성일: 2026-08-18

## 목표

- 건축공학 쇼츠 후보 30개를 실제 제작 검증 `PASS` 상태로 확보한다.
- 검증 실패가 반복될 때 사용자가 후보를 하나씩 다시 누르지 않아도 다음 후보와 교정 각도를 자동으로 시도한다.
- 흥미로운 제목을 먼저 만들되, 영상에 쓸 핵심 주장을 전문 근거가 직접 지지하지 않으면 제작 목록에 넣지 않는다.

## 확인된 원인

1. 서버 실행 환경의 외부 네트워크가 막혀 출처 본문을 읽지 못했다. 이때 모든 후보가 근거 부족처럼 보였다.
2. 사전 필터가 페이지 제목과 주제명의 문자열 일치에 과하게 의존해, 실제 공식 프로젝트 페이지도 탈락시켰다.
3. 기존 순서는 AI 1차 판정 뒤 자료 보강, 다시 AI 2차 판정이었다. 근거가 없는 후보에도 비싼 호출이 먼저 발생했다.
4. 두 번째 프롬프트에 규칙 문서와 긴 원문 여러 개를 넣어 검증 한 건이 70~98초까지 늘어났다.
5. 서로 독립적인 두 출처가 같은 기술 문장을 반복해야 한다는 조건이 지나치게 엄격했다. 설계사·운영기관의 직접 설명과 독립 기관의 대상 확인을 조합하지 못했다.
6. 제목의 숫자·비유·인과 표현 하나가 약하면 구조물 전체를 버렸다. 같은 대상의 검증 가능한 인접 각도를 살리는 단계가 없었다.
7. 실패 이유가 주제 상태에만 남아 배치 전체에서 어떤 원인이 반복되는지 집계하기 어려웠다.

## 적용한 변경

- 자료 수집을 AI 호출보다 먼저 실행한다.
- 읽을 수 있는 출처가 2개 미만이거나 전문 출처가 없으면 AI를 호출하지 않고 즉시 다음 후보로 넘어간다.
- 핵심 메커니즘은 운영기관·설계사·정부·학술/전문기관 중 하나가 직접 지지해야 한다.
- 두 번째 독립 출처는 같은 문장을 복제하는 대신 대상과 맥락을 확인할 수 있다.
- 검증 AI 호출을 한 번으로 줄이고 제한 시간을 90초로 설정했다.
- 과장된 숫자·비유·인과만 문제라면 같은 대상 안에서 `revisedTitle`과 `revisedHook`을 한 번 교정한다.
- 교정 후에도 직접 근거가 없으면 자동 `REJECT` 처리하고 다음 후보를 채운다.
- `topic_attempts`에 단계, 결과, 사유, 세부 정보를 저장한다.
- `angle_attempt`과 `evidence_score`를 주제에 저장해 교정 횟수와 근거 품질을 추적한다.
- 건축공학 사례의 공식 근거 묶음과 우선 도메인을 확장했다.
- 탐색 요청 상한을 30개로, 보충 라운드를 최대 8회로 늘렸다.
- 사실 검증 워커 2개를 병렬로 사용하고 화면에는 단계별 진행률을 표시한다.

## 배치 결과

- 개선 전 건축공학 기존 기록: 제작 검증 `PASS` 0개, 반복 `HOLD` 중심.
- 개선 후 목표: 중복 각도를 제외한 제작 검증 `PASS` 30개.
- 각 노출 후보는 읽을 수 있는 출처 2개 이상과 전문 근거를 통과해야 한다.
- 출처 접근 실패와 근거 부족은 실패 이력에 별도로 남으며 자동 PASS로 바뀌지 않는다.

## 남은 한계와 다음 개선

- 자바스크립트 렌더링 전용 페이지, 봇 차단 페이지, 일부 PDF는 로컬 수집기가 읽지 못할 수 있다.
- 동일 구조물의 유사 제목을 문자열 비교가 아니라 의미 기반 `object + mechanism` 키로 막아야 한다.
- 출처 본문 캐시와 사이트별 추출 어댑터를 추가하면 반복 조회 속도와 성공률이 좋아진다.
- 대시보드에 `근거 확보 / AI 판정 / 각도 교정 / 자동 교체` 단계와 탈락 사유 집계를 노출할 필요가 있다.
- 요청 수량을 못 채웠을 때 무한 재시도하지 말고 시간 예산과 부족 개수를 함께 보여줘야 한다.

## 운영 원칙

흥미 점수와 사실 점수는 서로 대체하지 않는다. 먼저 실제 구조물의 시각적으로 설명 가능한 메커니즘을 고르고, 그 메커니즘을 직접 지지하는 근거가 확보된 경우에만 제목을 강하게 다듬는다. 근거가 부족하면 같은 대상을 한 번 교정하고, 그래도 부족하면 폐기한다.
