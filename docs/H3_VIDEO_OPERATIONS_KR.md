# MiniMax H3 CLEAN 영상과 INFO 합성 운영 기준

기준일: 2026-08-17

## 목적

MiniMax H3 영상은 승인 CLEAN을 첫 프레임으로 사용하는 장면 단위 I2V 산출물이다. 동일 구도의 승인 INFO는 생성 모델에 넣지 않고 투명 가이드와 라벨 레이어로 분리해 FFmpeg 후처리로 합성한다. 둘 중 하나가 없거나 검수 상태가 `OK`가 아니면 큐에 등록하지 않는다. 생성 성공만으로 완료 처리하지 않고 자동 QC, 프로필과 시드를 기록한 뒤 사람이 MP4를 승인해야 다음 단계로 보낸다.

4초 생성은 CLEAN 영상으로 시작하고, 후처리에서 가이드가 먼저 나타난 뒤 작은 라벨과 값이 조립되는 순서를 따른다. 한글과 수치는 생성 모델이 그리지 않는다.

## 생성 프로필

| 프로필 | 구성 | 용도 |
| --- | --- | --- |
| 품질 | 기본 H3, 20스텝, 0.86MP, 네이티브 attention | 최종 후보와 품질 기준 |
| 균형 | LightX2V Turbo LoRA, 8스텝, 0.86MP, 메모리 절약 attention | 품질과 시간 비교 |
| 빠름 | LightX2V Turbo LoRA, 4스텝, 0.86MP, 메모리 절약 attention | 움직임 초안 |

기본 선택은 품질이다. Turbo LoRA와 기본 H3 결과는 단순한 속도 차이가 아니므로 별도 품질 특성을 가진 프로필로 취급한다.

## 비교 절차

1. 대표 장면 하나를 고른다.
2. 같은 CLEAN 이미지와 영상 프롬프트를 사용한다.
3. 빠름, 균형, 품질 순으로 생성한다.
4. 생성 시간, 원본 구도 유지, 얼굴과 손, 시대 고증, 움직임, 깜빡임을 비교한다.
5. 프로젝트 기본 프로필을 정한 뒤 나머지 장면을 생성한다.

## 검수 게이트

- `pending`: 생성 완료, 미검수
- `approved`: 편집 단계 사용 가능
- `rejected`: 재생성 필요

구도와 인물 유지, 얼굴·손·사물 변형, 시대에 맞지 않는 물건과 문자, 카메라 움직임과 깜빡임을 확인한다. 시스템은 ffprobe로 MP4 길이, 해상도, 비디오 코덱, 오디오 유무와 파일 크기를 자동 기록한다.

## 버전 보존

재생성 결과는 기존 MP4를 덮어쓰지 않고 `_run-{timestamp}.mp4` 파일로 저장한다. 대시보드는 해당 장면의 최신 완료 작업을 보여주며 이전 작업의 프로필, 설정, 시드와 결과 파일은 이력으로 남긴다.

큐 등록 시 승인 CLEAN과 INFO의 SHA-256 입력 지문을 저장한다. 생성 전후 지문이 달라지면 작업은 `stale`로 끝나며 편집 후보로 선택되지 않는다.

## OpenShot 인계

- MP4는 정상 속도 1배로만 재생한다.
- TTS 기반 장면표 구간에 맞춰 `sourceStart=0`부터 필요한 길이만 트림한다.
- 한 프레임 허용오차를 넘겨 원본 영상이 짧으면 인계를 중단하고 재생성을 요구한다.
- INFO는 MP4 안에 이미 합성되어 있으므로 별도 정지 이미지 트랙을 추가하지 않는다.

## 가속 기능 도입 원칙

Spectrum, Sol Attention과 업스케일러는 한 번에 중첩하지 않는다. 동일 입력 A/B 테스트에서 품질과 안정성을 확인한 뒤 별도 프로필로 추가한다. LTX 업스케일은 승인된 최종 영상에만 선택적으로 적용한다.
