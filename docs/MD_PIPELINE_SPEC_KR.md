# 원본 MD 준수 제작 규격

기준 문서: `CODEX_ENGINEERING_SHORTS_WORKFLOW_KR.md`

이 문서는 원본 MD를 대시보드가 실행할 수 있는 승인 게이트로 정리한 제품 계약이다. 다른 제품 계획이나 MVP 문서가 이 규격과 충돌하면 이 문서를 우선한다.

## 고정 파이프라인

```text
주제와 핵심 논지
-> 조사와 주장별 사실 검증
-> 대본 승인
-> TTS 생성과 실측
-> 물리 상태 기반 장면표 승인
-> CLEAN 프롬프트와 이미지 승인
-> 동일 CLEAN 기반 INFO 편집과 승인
-> CLEAN 기반 4초 영상 생성과 정확한 INFO 레이어 합성
-> MP4 실제 화면 승인
-> TTS 기준 편집 인계
```

## 승인 게이트

1. 검증된 핵심 주장 없이는 대본을 만들 수 없다.
   보강 검색과 2차 검증까지 핵심 근거가 부족한 HOLD 후보는 제작 목록에서 자동 폐기한다.
2. 승인된 대본 없이는 TTS를 만들 수 없다.
3. 실제 TTS 없이는 장면표를 만들 수 없다.
4. 승인된 장면표 없이는 CLEAN 프롬프트를 확정할 수 없다.
5. 모든 CLEAN이 승인되지 않으면 INFO 단계가 잠긴다.
6. 모든 INFO가 동일 구도 편집본으로 승인되지 않으면 영상을 만들 수 없다.
7. 영상은 CLEAN을 첫 프레임으로 사용하고, 승인 INFO의 가이드와 라벨 레이어를 후처리로 합성한다.
8. 승인되지 않은 MP4는 편집 완료 자산으로 계산하지 않는다.

## 장면 생성 원칙

장면 수는 TTS 초 수로 계산하지 않는다. 새로운 물리 상태, 하중 경로, 작동 단계, 내부 단면, 매크로 메커니즘, 규모 비교 또는 강한 인과 전환이 있을 때만 새 장면을 만든다. TTS 실측은 생성된 장면의 편집 구간을 배분하는 데만 사용한다.

## 대본 서사 계약

- 모든 주제를 억지로 문제 해결형으로 만들지 않는다. `문제-해결`, `설계 제약`, `숨은 메커니즘`, `실패 분석`, `진화 비교`, `공정 분해` 중 근거와 시각화에 맞는 유형을 먼저 고른다.
- 문제 해결형은 원인 또는 배경, 눈에 보이는 문제, 기존 접근의 한계, 개입, 작동 원리, 결과 순서를 기본으로 한다. 출처가 뒷받침하지 않는 원인은 만들지 않는다.
- 길이는 내용 우선으로 30~180초 범위를 추천한다. 초과 시 `extension`, `supporting`, `essential` 순으로 줄이고 핵심 인과를 먼저 보존한다.
- `아~ 어질어질합니다.`는 문제가 최고조에 이르고 시청자가 왜 어려운지 이해한 뒤 한 번만 쓴다.
- `그래서 생각의 판을 완전히 엎었습니다.`는 실제 해결책이 상식과 반대이거나 발상 전환인 경우, 앞에서 누적한 문제의 결론으로 자연스럽게 이어지도록 해결 원리 직전에 한 번만 쓴다.
- 두 문구가 어울리지 않는 서사에서는 사용하지 않는다.

## INFO 그래픽 계약

- INFO의 기본값은 `none`이다. CLEAN과 영상의 실제 변화만으로 장면 의미가 읽히면 오버레이를 추가하지 않는다.
- 같은 TTS 구간에는 INFO 장면을 최대 1개만 사용한다. 도입 구간은 라벨 없이 문제와 대상을 먼저 보여준다.
- INFO는 보이지 않는 하중 경로, 인과 방향, 동일 기준의 전후 차이처럼 그래픽 없이는 정확히 읽기 어려운 관계에만 사용한다.
- 제작용 좌우·방위 연속성은 화면 라벨과 분리한다. 보이는 물체 이름, 방위, 내레이션 반복 문구를 명찰처럼 붙이지 않는다.
- 라벨은 최대 2개로 제한하며, 검증되지 않은 수치보다 실제 변화 간격과 공간 관계를 우선한다.
- INFO는 자유로운 재생성이 아니라 승인 CLEAN 위에 적용할 구조화된 오버레이 명세다.
- 명세에는 유형, 정확한 라벨, 기준점, 방향 규칙, 비교 규칙, 금지 결과가 포함된다.
- 금지 표시의 화살표는 금지된 접촉점 또는 행동을 정확히 가리켜야 한다.
- 전후 비교는 같은 기준선과 이전/이후 위치를 함께 표시하고 실제 변화 간격을 보여줘야 한다.
- 장식용 화살표, 의미 없는 흐름선, 저대비 글자, 명세에 없는 라벨은 허용하지 않는다.
- INFO의 모든 한글 라벨은 Pretendard SemiBold, 숫자·단위·강조값은 Pretendard Bold를 사용한다. 다른 장식용 글꼴은 사용하지 않는다.
- 파일·합성 QC는 CLEAN 바깥 픽셀 보존, 오버레이 결정론적 합성, 라벨 명세 일치, 화면 경계, 자막 안전영역, 라벨 겹침, 대비, 가이드 기하와 숫자 근거 연결을 검사한다. 이 검사는 INFO의 내용 필요성을 대신하지 않는다.
- 자동 QC를 통과한 전체 INFO만 한 번에 승인할 수 있다. 한 장면을 교체하면 그 장면의 기존 영상은 `stale` 처리한다.

## 자막 계약

- 자막은 이미지나 영상 생성 단계에 굽지 않고 최종 편집 단계에서 추가한다.
- 실제 TTS 세그먼트 길이를 기준으로 SRT/VTT를 생성하고, 한 큐는 최대 2줄로 제한한다.
- 기본 프리셋은 문화재돌봄체 굵은체(`MunhwajaeDolbom Bold`)이며 OpenShot Caption 효과에도 실제 TTF 경로, 동일 타이밍과 스타일을 전달한다.
- 글꼴이 설치되지 않은 환경에서는 맑은 고딕 Bold로 대체하며, 편집기에서 문구와 타이밍을 수정할 수 있어야 한다.

## 자산 불변 조건

- CLEAN은 텍스트와 그래픽이 없는 원본이다.
- INFO는 CLEAN을 새로 그린 이미지가 아니라 동일 구도 편집본이다.
- 영상의 실제 첫 프레임은 CLEAN이며, 마지막 구간의 INFO 구성은 결정론적 후처리 레이어다.
- 모든 산출물은 `S ID`, `KF ID`, `CLIP ID`로 연결한다.
- 상위 산출물이 바뀌면 하위 산출물은 삭제하지 않고 `stale` 처리한다.

## 최종 편집 길이 계약

- H3 MP4는 정상 속도 1배를 유지한다. 배속, 프레임 보간, 마지막 프레임 정지로 길이를 맞추지 않는다.
- 장면표의 TTS 구간만큼 각 MP4의 시작과 끝을 트림한다.
- MP4 원본 길이가 장면 구간보다 짧으면 OpenShot 프로젝트를 만들지 않고 해당 장면 재생성을 요구한다.
- 검증 INFO는 이미 MP4 안에 합성되어 있으므로 OpenShot에 별도 INFO 정지 이미지 트랙을 만들지 않는다.
